# job-hunting

転職活動用の資料を AI と共同作成するリポジトリ。

## ディレクトリ構成

```
job-hunting/
├── input/          # 入力用生データ（エージェント提供の履歴書・スキルシートなど）
├── output/         # AI が生成した成果物（職業履歴書・スキルセットまとめなど）
└── reference/      # 調査資料・企業情報・進め方メモなど参照用ドキュメント
```

| ディレクトリ | 用途                                              |
| ------------ | ------------------------------------------------- |
| `input/`     | 外部から受け取った資料や自分の生の情報を置く      |
| `output/`    | Claude Code で生成・整形した最終成果物を置く      |
| `reference/` | 各種調査資料を蓄積し、AI との相談や分析に活用する |

## 開発環境

- VS Code + Peacock（ウィンドウカラー: `#1a237e`）

## 設計思想

このリポジトリは、職務経歴書を一発で生成するためのものではなく、
「経験の素材を蓄積して、応募先企業ごとに再構成するための仕組み」を目指しています。

- `dictate.py` で音声を録音し、文字起こしした生テキストを `output/dictations/` に蓄積する
- `input/` の既存職務経歴書やテンプレートをベースとして、経験の再利用可能な素材を整える
- 応募先企業の JD から求められる人物像を抽出し、どの経験を前面に出すかを戦略化する
- 最終的な職務経歴書は、企業ごとの狙いに合わせて再構成する

つまり、ここでの「生成」は、最終文書をそのままコードで作ることではなく、
経験のプールから必要な事実・ストーリー・表現を選び、企業ごとの文脈に合わせて再編集することを意味します。

スクリプト側でやるべきことは「音声入力 → テキスト化 → 保存」までで、
最終的な書き分けや職務経歴書の再構成は LLM / Claude Code の対話で行う前提です。

これは、企業ごとに強調したい観点が異なるためです。
たとえば、AI系企業では技術のインパクトや定量的成果を前面に出し、
研究寄りの企業では課題解決や実験・分析の深さを強調する、というように
同じ経験でも、伝え方を変えるべきだからです。

### ワークフロー

### 職務経歴書作成フロー

```
音声入力（記憶の棚卸し）
    ↓ dictate.py（MLX Whisper でローカル文字起こし）
output/dictations/（生テキスト蓄積）
    ↓ Claude Code に一括処理させる
output/career-history.md（職務経歴書）
```

1. `dictate.py` を実行し、2016年以降の経験・出来事を時系列・粒度を気にせず音声で全部吐き出す
2. `output/dictations/` に蓄積した全テキストと `input/` の既存職務経歴書を Claude Code に読ませる
3. 既存フォーマットを参照しながら職務経歴書を生成・更新する

> 中間的な構造化ステップは設けず、生テキスト → 成果物の2ステップで管理する。
